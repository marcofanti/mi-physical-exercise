# ExerciseCoach — iOS Port of the CAMI MI Exercise Chatbot

A native iPhone app that ports the Streamlit motivational-interviewing (MI)
exercise chatbot (`../../exercise_app.py`) to iOS, running the counselor
entirely **on-device** with Apple's Foundation Models framework. No server, no
API key, no data leaving the phone.

## Features

- **Chat with the MI counselor** — same one-call-per-turn brain as the Python
  app: readiness stage inference (TTM), barrier classification against the V8
  decision tree, MI strategy selection, and a <80-word counselor reply, all in
  one guided-generation request.
- **MI state panel** — chip row (stage / barrier / strategy) above the chat;
  tap for the detail sheet with rationale, confidence, current path, and the
  full decision tree with the active path highlighted.
- **Session history** — conversations persist on-device in SwiftData.
- **Full voice conversation** — hands-free loop with on-device
  SpeechAnalyzer/SpeechTranscriber STT and AVSpeechSynthesizer TTS. Tap the mic
  to start; tap again while it speaks to interrupt.
- **HealthKit grounding** — optional read-only access to steps/workouts adds
  one activity line to the prompt.
- **Check-ins** — when the client reaches Preparation, a "Commit to a next
  step" affordance schedules a local notification; tapping it seeds a
  follow-up session.

## Build

The Xcode project is generated from `project.yml`:

```bash
cd ios/ExerciseCoach
xcodegen generate
open ExerciseCoach.xcodeproj
```

Command-line build and test:

```bash
xcodebuild build -project ExerciseCoach.xcodeproj -scheme ExerciseCoach \
    -destination 'platform=iOS Simulator,name=iPhone 17 Pro'

xcodebuild test -project ExerciseCoach.xcodeproj -scheme ExerciseCoach \
    -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

The unit tests pin Python parity: decision-tree labels and `LEAF_PATH_TEXT`
byte-for-byte, fallback-classifier outputs (including tie-break behavior),
prompt formats, and sanitizer defaults. Expected values were generated by
running the reference functions in `../../exercise_app.py`.

## Architecture

```
ExerciseCoach/
├── App/            entry, availability gate, notification routing, disclaimer
├── Models/         Stage/Strategy enums, static V8 DecisionTree, @Generable
│   │               CounselorTurn schema
│   └── Persistence/ SwiftData @Models: ChatSession, ChatMessage,
│                    TurnMetadata, CommittedStep
├── Services/       CounselorEngine (Foundation Models), PromptBuilder,
│                   FallbackClassifier, SpeechInput/Output,
│                   VoiceConversationController, HealthContextProvider,
│                   NotificationScheduler
├── ViewModels/     ChatViewModel
└── Views/          ChatView, MI chips/detail sheet, DecisionTreeView,
                    SessionListView, CommitStepSheet, VoiceModeOverlay
```

Key design decisions (mirroring the Python app):

- **Stateless per turn**: each turn uses a fresh `LanguageModelSession` whose
  instructions embed the tree; the prompt carries only the last 6 messages.
  Stays far under the ~4k-token on-device context window; the next session is
  prewarmed after every reply for latency.
- **Guided generation**: `@Guide(.anyOf(...))` constrains stage, strategy, and
  the barrier leaf to valid values by construction — no JSON repair needed.
- **Fallback path**: any model failure degrades through the keyword classifier
  (verbatim port of `FALLBACK_KEYWORDS`) plus templated replies; raw errors
  never reach the chat.

## TestFlight

1. In Xcode, set your team on both targets (automatic signing;
   bundle id `com.mfanti.exercisecoach`).
2. Product → Archive → Distribute App → TestFlight.
3. App Privacy in App Store Connect: **Data Not Collected** (everything is
   on-device: model, speech, health data, storage).
4. "What to Test" notes for testers:
   - Requires iPhone 15 Pro or later, iOS 26, Apple Intelligence enabled.
   - Script: (1) "my class schedule is insane" → Schedule Constraints barrier
     in the chip row; (2) "I don't see the point, I feel fine" →
     Precontemplation, no plan pushed; (3) "I could try a 10-minute walk
     tomorrow" → Preparation → commit affordance → notification fires;
     (4) voice mode round-trip + interrupt; (5) Airplane mode — everything
     still works.

## Relation to the Python app

| Python (`exercise_app.py`) | Swift |
|---|---|
| `STAGES` / `STRATEGIES` | `MITypes.swift` |
| `parse_markdown_tree` + `V8-Decision Tree.md` | `DecisionTree.swift` (static) |
| `FALLBACK_KEYWORDS` + `fallback_classification` | `FallbackClassifier.swift` |
| system/user prompts | `PromptBuilder.swift` |
| `infer_and_respond` | `CounselorEngine.swift` |
| `st.session_state` | `ChatViewModel` + SwiftData |
| sidebar tree/metrics | `MIStateChipsView` + `MIDetailSheet` |

The one-call-per-turn contract and all fallback behavior are ported verbatim;
deviations (leaf-name generation instead of free-form path strings, dropped
"Return only JSON" instruction) are documented in code comments where they
occur.
